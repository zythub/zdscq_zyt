## 2. 数据库连接

### 2.1 本地命令行

```bash
# PostgreSQL / OpenGauss
gsql -p 54321 -U omm -d gaussdb

# 设置默认 schema
SET search_path = plant;

# MongoDB
mongo -u plant -p '<密码>' --authenticationDatabase admin plant
```

### 2.2 WorkBuddy MCP 连数据库

WorkBuddy 已支持 `mcp__dbx` 数据库连接器。让 AI 帮你查表时：

1. 先确认连接名：`mcp__dbx__dbx_list_connections`
2. 让 AI 列出表：`mcp__dbx__dbx_list_tables`
3. 让 AI 描述表结构：`mcp__dbx__dbx_describe_table`
4. 再让它执行查询：`mcp__dbx__dbx_execute_query`

**必须告诉 AI 的信息**：

- 数据库类型：PostgreSQL / MySQL / MongoDB / 达梦
- Host / Port / 数据库名 / schema
- 账号 / 密码（如允许）
- 查哪张表、查什么字段

**示例话术**：

> 用 mcp__dbx 连测试 PG（host=<内网地址>，port=<端口>，db=gaussdb，schema=plant），查 `tma_storage_out` 表的字段和最新 5 条数据。

### 2.3 资料库编号工具环境切换

## 3. 浏览器连接（BrowserSkill）

### 3.1 前置条件

1. Chrome 已安装 BrowserSkill 扩展，且扩展显示「已连接」。
2. `bsk` 已加入 PATH（Rust CLI）。
3. 扩展弹出面板绿色 → 表示已连上 daemon。

### 3.2 检查连接

```bash
bsk status          # 看 daemon 是否启动
bsk browsers        # 看已连接的浏览器
bsk doctor          # 深度诊断
```

### 3.3 标准会话流程

```bash
# 1) 启动会话，记下 4 位 session id
bsk session start --no-focus

# 2) 所有命令都加 --session <id>
bsk navigate "http://<内网地址>/web/#/custom/form-definition/design" --session xxxx --wait-until domcontentloaded
bsk snapshot --session xxxx
bsk click @e123 --session xxxx

# 3) 结束会话（必须）
bsk session stop xxxx
```

### 3.4 查表单的常用命令

```bash
# 定位搜索框、查“出库”表单
bsk fill @e335 --value "出库" --session xxxx
bsk click @e338 --session xxxx      # 点查询
bsk snapshot --session xxxx          # 看结果

# 进入表单设计器
bsk click @e351 --session xxxx      # 编辑按钮
bsk click @e7 --session xxxx       # 表单设计

# 用 JS 抓表单定义
bsk evaluate "fetch('/apis/dynamic/form/{formId}',{headers:{'Authorization':'Bearer <你的Token>'}}).then(r=>r.json()).then(d=>{localStorage.setItem('__form',JSON.stringify(d.data));return d.data.id;})" --session xxxx
```

### 3.5 让 AI 用浏览器帮你干活

如果你说不清页面结构，直接让 AI：

1. 连浏览器 MCP（`agent-browser` skill 或 `bsk`）。
2. 截图给你确认位置。
3. 抓取你需要的表单字段、事件代码、按钮事件。

**示例话术**：

> 用 BrowserSkill 打开 <http://<内网地址>/web/#/custom/form-definition/design>，搜索「出库」表单，进入设计器，把 created 事件和 beforeSubmit 事件的代码抓出来。

## 4. 排查方法

### 4.1 改了表单不生效

1. 浏览器强刷 `Ctrl+Shift+R`。
2. 清 localStorage：`localStorage.clear()`（F12 → Application → Clear site data）。
3. 检查发布页：表单是否「已发布」。
4. 检查保存接口返回值：
   - 200 但内容没改 → 看是否改错环境/是否缓存
   - 405 → 路径错了，应为 `PUT /apis/dynamic/form`
   - 401 → Token 过期

### 4.2 出库/库存异常

1. 抓最新一条出库数据，看 `state`、`ckzt`、`type`。
2. 查 `tma_requisition_details.avail_stock_count`。
3. 查 `tma_material_stock.available_stock / actual_stock`。
4. 看流程节点状态。

### 4.3 自定义接口报错

1. 复制 SQL 到 `gsql` 手跑。
2. 检查 `#{参数}` 是否都有传值。
3. 检查存储过程是否在 PG 里已创建：`\df`。
4. 看 `sys_application_log` / `sys_business_log` 慢 SQL。

### 4.4 表单控件 id 不一致

1. 不要硬编码 id。
2. 用 `getControlIdByField` 动态查。
3. 批量改脚本时，通过 API 的 `formAttributeJson` 实时解析，不要跨环境复用 id。

## 6. 何时该连 MCP

- AI 不知道具体表结构 → **连数据库 MCP**。
- AI 不知道页面上控件 id / 事件代码 → **连浏览器 MCP**。
- AI 给的代码跑不通 → 让它拿真实数据再改，不要硬编。

**核心原则**：不确定就查，不要编。
