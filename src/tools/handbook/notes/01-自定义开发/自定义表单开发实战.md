## 1. 核心概念：instanceId vs dataBind（最重要）

| 术语 | 是什么 | 示例 |
| :--- | :--- | :--- |
| **instanceId** | 系统生成的控件唯一 ID，**始终不变** | `input_ah2wl95gdra4f` |
| **dataBind** | 控件与后端字段的逻辑绑定标识 | `flow_purchase.ID`（主表顶层）/ `flow_purchase_product.name`（子表行内） |
| **Instance** | 控件运行时对象，含全部 `props` | `ctx.getInstance(id)` 获取 |

**实测结论**：`getValue/setValue/getInstance` 等里 **instanceId 始终可靠**；dataBind 能否命中取决于查找链，
子表行内、特殊字符、嵌套 state 都会失配返回 `undefined`。

```js
// ✅ 推荐：instanceId（最稳）
const inst = ctx.getInstance('input_ah2wl95gdra4f');
const val  = ctx.getValue('input_ah2wl95gdra4f');

// ⚠️ 可用但有局限：dataBind（仅主表顶层可靠）
const val2 = ctx.getValue('flow_purchase.ID');

// 🔥 危险：子表行内字段用 getValue 必失败（真实路径带行号）
ctx.getValue('flow_purchase_product.name'); // => undefined
```

**判断规则**：主表顶层 → `ctx.getValue / setValue / visibles / ...`；子表行内 → 必须用
`getArrayValue / setArrayValue / getArrayInstance / setArrayInstance`（§5）。

## 2. 事件列表（全部 19 个）

事件在控件 `props.events` 按 `event` key 注册，签名统一 `module.exports = function (params, ctx, block) {...}`。

### 用户触发

| 事件 | 触发时机 | params 关键字段 | 典型用途 |
| :--- | :--- | :--- | :--- |
| `CLICK` | 点击控件 | `params.value` | 提交、Tree 节点点击 |
| `CHANGE` | 值变化 | `params.value`（官方文档另写 `params.oldValue`，**实测不存在**） | 联动、动态校验 |
| `FOCUS` | 获焦 | `params.value` | 缓存旧值（见 §8）、帮助信息 |
| `BLUR` | 失焦 | `params.value` | 实时校验 |

### 表单周期

| 事件 | 触发时机 | params 关键字段 |
| :--- | :--- | :--- |
| `CREATED` | FormView 首次挂载完成 | — |
| `BEFORE_SUBMIT` | 提交时、校验通过后 | `params.value` = **提交数据对象**（取它，不要取 `params.args[0]`，✅ 实测） |
| `AFTER_SUBMIT` | 提交 callback resolve 后 | — |

> `BEFORE_SUBMIT` 返回值：`false` = 阻断提交；返回对象 = 用它替代 submitValue；`undefined` = 正常提交。
> 校验失败 / `BEFORE_SUBMIT` 返回 false 时 `AFTER_SUBMIT` 不触发。

### 子表（自增组件）事件

| 事件 | 触发时机 | params |
| :--- | :--- | :--- |
| `ADD_ROWS` | 新增行 | `params.args[0].list` |
| `REMOVE_ROWS` | 删除行 | `params.args[0].list` |
| `SELECT_ROWS` | 行被选中 | `params.args[0]` |

> 触发源含 `append/prepend/insert/update/replace/rowAppend/remove`；**swap/move/hidden 不触发**。

### 组件生命周期 / 上传 / 按钮 / 视图

| 事件 | 触发时机 | 备注 |
| :--- | :--- | :--- |
| `MOUNTED` | 控件挂载完成 | 取值时序比 CREATED 稳 |
| `UNMOUNTED` | 控件卸载 | params 不含 value/getValue 等 |
| `BEFORE_UPLOAD` | 上传前 | `return false` 阻断上传 |
| `UPLOAD_SUCCESS` / `UPLOAD_FAIL` / `DELETE_FILE` | 上传成功/失败/删除文件 | 典型：成功后写文件 id、删除时清值 |
| `SELECTED` | 多选按钮切换 | 仅切换型按钮有效 |
| `TABCHANGED` | 标签页切换 | `params.value` = 新 key |
| `VIEW_MODE_CHANGE` | 编辑态↔查看态 | `params.value.isView` |

### 返回值规则

- **仅 `BEFORE_SUBMIT` 和 `BEFORE_UPLOAD` 的返回值有意义**；其余 17 个事件返回值被丢弃
  —— 想在 `ADD_ROWS` 里 `return false` 拦新增？拦不住（§5.2 的正确做法是自己接管新增按钮）。
- 同一事件多个处理器按 `props.events` 数组顺序执行。

### params（事件上下文）

| 成员 | 说明 |
| :--- | :--- |
| `params.value` | 触发时刻的**快照值**（CHANGE = 新值；只读语义，赋值不写回） |
| `params.oldValue` | ⚠️ **实测不存在**。要旧值用 FOCUS 缓存法（§8） |
| `params.getValue()` / `params.setValue(v)` | 取/改**当前控件**最新值 |
| `params.index` / `params.row` | 仅子表内：当前行号 / 当前行数据（实时 getter） |
| `params.instance` / `params.getInstance()` | 当前组件实例（含 `props`） |
| `params.parent` | 父级实例（子表内 = 子表实例） |
| `params.setInstance(prop, value)` | 改当前组件属性 |
| `params.disabled/required/options(v?)` | 快捷读写（`props` 含该 key 才存在） |
| `params.validate()` | 校验当前组件（仅 FormControl/FormView） |
| `params.deleteCurrentRow()` 等 | 子表行级方法（见 §5.3） |

### 2.18 选择弹窗 input 禁手输：DOM setAttribute("readonly")（✅ 实测 2026-10-28）

场景：控件开了「选择弹窗」（`isSelectModal` + `selectDataSource`），要求**只能弹窗选、不能手输**。

试过都**不行**的路子：

- 设计器勾 `readonly` / `disabled`：平台把弹窗按钮（input 内部的 down 图标）**一起禁掉**，弹窗点不开；
- created 里 `ctx.setInstance(id, "readonly", true)`：同上，按钮一起死；
- CSS `pointer-events: none` + 把弹窗按钮铺满控件区：只挡鼠标、**键盘照样输**，手快的人在弹窗出来前就能敲进去；
- keydown 拦截 / blur 定时器驱逐焦点：能治但丑，还要防输入法上屏。

**终解**：created（初始化）里直接用 DOM 给 input 设**原生 readonly** —— 绕过平台控件层，浏览器原生禁键盘；弹窗按钮（`anticon-down`）是 input 的**兄弟元素**，完全不受影响：

```js
module.exports = function (params, ctx, block) {
  var el = document.querySelector("span.input_<控件id> > input");
  if (el) el.setAttribute("readonly", true);
};
```

- 选择器：wrapper 是 `span.input_<控件id>`，input 是它的子元素（结构以 F12 实际为准）；
- `if (el)` 判空兜底：极端情况 created 时 DOM 未渲染完取不到，包一层 `setTimeout(() => { … }, 200)` 再取；
- 配套建议：保存点击前校验「弹窗 id 隐藏字段非空」，防历史脏值（手输过、没 id 的）入库。

### 2.19 选人控件（org）按人员白名单过滤（✅ 实测 2026-10-29）

场景：选人控件要**只允许选指定几个人**（白名单），其他人在弹窗里不显示。

属性面板上的「自定义筛选」有**简单 / 高级两个页签**，关键坑：

- **普通版 `customFilterFn(users, orgs, pos)` 是废的** —— 实测它会**被调用**（console 有输出），但
  `users` 恒为空数组（`过滤前人数: 0 undefined`），写什么过滤都不生效；
- **真正带数据的是高级版 `customFilterFnAdvanced(params, ctx, block)`** —— 实测 `params` 结构：

```js
params = {
  users: Array(370),   // ✅ 人员全量，带 id
  orgs: Array(19),     // 部门树
  pos: Array(0),       // 岗位
  instance: {...},     // 控件实例
  value: "<当前值>",
}
```

**可用写法**（双保险：原地改 `params.users` + 返回对象，框架认哪个都能生效）：

```js
module.exports = function (params, ctx, block) {
  var allow = ["<人员id1>", "<人员id2>", "<人员id3>"];  // 白名单：要放行的人员 id
  var filtered = (params.users || []).filter(function (u) {
    var uid = u.id || u.userId;              // 两种字段名都兼容
    return allow.indexOf(uid) !== -1;
  });
  params.users = filtered;                                        // 形态 A：原地改
  return { users: filtered, orgs: params.orgs, pos: params.pos }; // 形态 B：返回对象
};
```

配套：

- 属性面板「自定义筛选」开关要**打开**（`customFilter: true`），否则函数不会被调用；
- 「简单」页签里的「编辑筛选条件」是**可视化条件编辑器**（配字段条件用，未与白名单混用实测）；
- 想再收窄部门范围：mounted 里 `ctx.setInstance("<org控件id>", "currentOrg", "<部门id>")`，与白名单**可叠加**（部门限定 + 人员白名单）；
- 调试口诀：先在两个函数里各打一行 `console.log`，看**谁有输出、谁有数据** —— 别在恒空的那个里死磕。

### 3.5 通过数据库字段名找控件 id —— `getControlIdByField`

> 控件 id 跨环境可能不一致，**不要硬编码**，实时解析。

```js
function getControlIdByField(formInstance, fieldName) {
  const stack = [formInstance];
  while (stack.length > 0) {
    const node = stack.pop();
    if (node.props?.dataField === fieldName && node.id) return node.id;
    if (node.children) for (const c of node.children) stack.push(c);
  }
  return undefined;
}

// 用法（可挂 ctx.utils 复用）
ctx.utils.getControlId = getControlIdByField;
const gcmcId = ctx.utils.getControlId(params.instance, "gcmc");
const gcmc = gcmcId ? ctx.getValue(gcmcId) : undefined;
```

## 5. ctx 子表（ArrayForm）

> 行自带不可见 `$internal_id`（用户代码不读写）。有隐藏行（`hidden`）时**可见行号 ≠ 底层索引**，行操作按可见行号。

### 5.1 读 / 写：`getArrayValue / setArrayValue`

```js
ctx.getArrayValue('sub_xxx');                      // 全部行（key = 控件id）
ctx.getArrayValue('sub_xxx', 0);                   // 第 0 行
ctx.getArrayValue('sub_xxx', 0, 'sub_xxx.name');   // 第 0 行某字段

ctx.setArrayValue('sub_xxx', [{...}, {...}]);                        // ③ 替换全部（等价 replace）
ctx.setArrayValue('sub_xxx', 0, 'sub_xxx.name', '新值');             // ① 改单格
ctx.setArrayValue('sub_xxx', 0, { 'sub_xxx.name': 'x', 'sub_xxx.num': 10 }); // ② 改整行多字段
ctx.deleteArrayRow('sub_xxx', 0);                                    // 删行
```

> ⚠️ ③ 会把**整个子表替换**、丢行——只用于全量重写/过滤。
> ①② 对每一行**异步触发 CHANGE**（值真变才触发）→ 先判 `!==` 再写。
> 行内读主表字段直接 `ctx.getValue("<主表字段id>")`（getValue 找不到会回落到全局）。

**✅ 实例：A 改 B，B 联动改 A（子表行内联动）**

```js
module.exports = function (params, ctx, block) {
  const rowIndex = params.index;
  const m = params.value == " blank-1" ? "√" : " ";
  ctx.setArrayValue("<子表id>", rowIndex, "<子表字段idA>", m);

  const oldVal = ctx.getArrayValue("<子表id>", rowIndex, "<子表字段idB>");
  const newVal = params.value == " blank-1" ? null : " blank-1";
  if (oldVal !== newVal) {
    ctx.setArrayValue("<子表id>", rowIndex, "<子表字段idB>", newVal);
  }
};
```

**✅ 实例：主表字段变化 → 整列同步给子表所有行**（挂主表字段的 CHANGE 事件）

```js
module.exports = function (params, ctx, block) {
  const SUB = "<子表id>"; const FIELD = "<子表字段id>";
  const rows = ctx.getArrayValue(SUB) || [];
  rows.forEach((row, index) => {
    if (row[FIELD] !== params.value) {          // 有变化才写，减少无谓 CHANGE
      ctx.setArrayValue(SUB, index, FIELD, params.value);
    }
  });
};
```

**✅ 实例：导入子表后，把主表字段值覆盖到所有行**（✅ 实测）

```js
// 基本版：写在「导入子表」按钮的点击后事件
module.exports = function (request, ctx, params) {
  const rows = ctx.getArrayValue("<子表id>") || [];
  rows.forEach((_, index) => {
    ctx.setArrayValue("<子表id>", index, "<子表字段id>", ctx.getValue("<主表来源字段id>"));
  });
};
```

> 两个实测坑：①「点击后事件」在点击那一刻就跑，而平台导入发生在点击**之后**——此刻读到的是旧子表
> → 用下面的轮询版；② 子表动作按钮的代码存在 **`actions[i].event`**（单个字段），不是 `events` 数组；
> 页面上"外面那个导入按钮"可能是页面级通用入口，不在 formAttributeJson 里，表单里挂事件不会被它触发。

```js
// 轮询版：等导入的行出现再覆盖
module.exports = function (request, ctx, params) {
  const SUB = "<子表id>"; const FIELD = "<子表字段id>";
  let tries = 0;
  const timer = setInterval(() => {
    const rows = ctx.getArrayValue(SUB) || [];
    if (rows.some((r) => !r[FIELD])) {          // 有行该字段还是空 = 刚导入进来的
      const val = ctx.getValue("<主表来源字段id>");
      rows.forEach((_, i) => ctx.setArrayValue(SUB, i, FIELD, val));
      clearInterval(timer);
    }
    if (++tries >= 40) clearInterval(timer);    // 最多等 20 秒
  }, 500);
};
```

```js
.then(() => {
  ctx.outInfo.reload();
  const waitForRows = (tries) => {
    const rows = ctx.getArrayValue(SUB) || [];
    if (rows.length === 0) {                        // 等 reload 落地
      if (tries <= 0) { ctx.message("子表未加载完成，请手动保存", "warning"); return; }
      setTimeout(() => waitForRows(tries - 1), 300);
      return;
    }
    let maxSeq = 0;                                 // 已有编号的最大号（别用行号，会撞号）
    rows.forEach((r) => {
      const m = (r[SUB_CODE] || "").match(/-(\d+)$/);
      if (m) maxSeq = Math.max(maxSeq, parseInt(m[1], 10));
    });
    let next = maxSeq + 1;                          // 只给空编号行赋号，保留已编号行
    for (let i = 0; i < rows.length; i++) {
      if (!rows[i][SUB_CODE]) {
        ctx.setArrayValue(SUB, i, SUB_CODE, prefix + "-" + ("00000" + next).slice(-5));
        next++;
      }
    }
    setTimeout(() => {                              // 等界面刷新再点保存
      const saveBtn = Array.from(document.querySelectorAll("button.ant-btn"))
        .find((b) => b.textContent.replace(/\s+/g, "") === "保存");
      if (saveBtn) saveBtn.click();
    }, 300);
  };
  waitForRows(20);
})
```

**导入后自动补值（dfBackfill 轮询，不依赖编号）**：导入走 `ctx.outInfo.reload()` 不经过 append，
新增逻辑不触发 → 在 `.then` 里 reload 后轮询补空值，天然幂等。**不要做"手动同步"按钮**（没人会点）。

```js
const before = (ctx.getArrayValue(SUB) || []).length;   // 点击那一刻的行数
let tries = 0, arrived = false, quiet = 0;
const timer = setInterval(() => {
  tries++;
  const r = ctx.utils.dfBackfill(false);                // 只补空字段
  if (r.rows !== before) arrived = true;                // 新行刷出来了
  if (arrived && r.filled === 0 && r.coded === 0) quiet++; else quiet = 0;
  if (quiet >= 2 || tries >= 60) clearInterval(timer);  // 30 秒兜底
}, 500);
```

> ⚠️ 停止条件不能只看"没东西可补"：导入前的老行本来有值，只判"补不动了"会在 1.5 秒误停。
> 正确条件 = 「行数相对导入前变化」+「连续 2 次无需再补」+ 总超时。

### 5.6 公共逻辑放哪：工具函数 vs 代码块

| 机制 | 存在哪 | 怎么调 | 谁可用 |
| :--- | :--- | :--- | :--- |
| 表单级工具函数 | `props.utilsJs[]` | `ctx.utils.块名(...)` | 任何脚本，含子表动作按钮 |
| 事件级代码块 | `events[].codeItem.utils[]` | `block.块名(...)` | 只有事件；**子表动作按钮拿不到 block** |

- 块第一个形参固定写 `ctx`（平台自动注入），可写 `async function (ctx)` 用 await。
- 分工：**共用纯逻辑 → ctx.utils；只此一处 → block**。

```js
// 工具函数 dfPad（props.utilsJs 里一条）
module.exports = function (ctx, n, len) {
  let s = "" + n;
  while (s.length < len) s = "0" + s;
  return s;
};
// 事件里：ctx.utils.dfPad(2, 5)
```

> `ctx.getArrayValue/setArrayValue/getArrayFormApi` 的**第一个字符串字面量必须是控件 id**
> （编辑器 lint 校验白名单），传变量绕过校验但传错照样失败——配对表集中到工具函数里一处维护。

## 8. 高频坑（FAQ）

### 事件不执行

1. 没用 `module.exports = function (params, ctx) {...}` 包裹；
2. 异步函数漏 `await`；
3. 绑错控件/事件类型（CHANGE 只对值变化控件，按钮用 CLICK）；
4. 被 `return false` 提前截断（BEFORE_SUBMIT 里）；
5. 语法错误（F12 Console 看红字）。
> 验证：脚本首行 `console.log('触发了', params.instance.id, params.value)`。

### getValue 返回 undefined（top 1 高频）

1. **用 dataBind 代替 instanceId**（最常见）→ 换 instanceId；
2. 用 `getValue` 读子表行内 → 改 `getArrayValue(table, index, field)`；
3. dataBind 与设计器实际填值不一致 → `ctx.getInstance(id).props.dataBind` 反查；
4. 字段本来就没值 → 先 setValue 再 getValue 验证；
5. **在 CREATED 里读**（时序问题）→ 改 MOUNTED/CHANGE 或 `setTimeout(...,0)`；
6. 传了 label 名；7. 子表 swap/hidden 后可见行号 ≠ 底层索引。

### CHANGE 里怎么拿「改之前的数」（params.oldValue 实测不存在）

用 **FOCUS + window 缓存**：FOCUS 在进入输入框时触发，那一刻值还是旧的；回写触发的第二轮
CHANGE 里新旧值相等天然跳过，不会死循环。

```js
// ① FOCUS 事件：进入编辑前记下当前值
module.exports = function (params, ctx, block) {
  if (!window.__prevValue) window.__prevValue = {};
  window.__prevValue[params.index] = params.value;   // 子表用行号做 key
};

// ② CHANGE 事件：取缓存里的旧值
module.exports = function (params, ctx, block) {
  const prev = (window.__prevValue || {})[params.index];
  if (prev === undefined) return;
  if (Number(params.value) > 100) {
    ctx.message('超出上限，已还原为 ' + prev, 'error');
    params.setValue(prev == null ? '' : prev);   // 必须用 params.setValue，别写 params.value =
  }
};
```

## 9. formAttributeJson 结构与代码存放位置

```jsonc
// 根节点 props：
"events": [
  { "event": "created",                 // 表单级事件挂根节点
    "scriptRefId": "",
    "codeItem": { "code": "module.exports = function (params, ctx, block) {...}", "utils": [] } }
],
"stylesheets": [ { "title": "main", "code": "/* css */" } ]
```

**三个代码存放位置必须分清**（排查"代码不执行"的钥匙）：

| 代码挂在哪 | 实际存储字段 |
| :--- | :--- |
| 子表**动作按钮**（`props.actions[]`） | `actions[i].event`（单个字符串，**没有** before/after 三段） |
| **控件事件**（字段/表单级 `props.events`） | `props.events[] = [{event, codeItem:{code}}]` |
| 表单**按钮控件**（toolbar button） | `props.events[]` 里的 `beforeClickEvent / clickEvent / afterClickEvent` |

> 子表动作按钮只有一个 event 槽——做不到"没编号时按钮置灰"（没有前置拦截点），只能点击后提示并 return。
> 事件代码写法铁律：`module.exports` 顶格；外壳内平铺直叙；**不要嵌套定义一堆命名函数**；
> 复用逻辑用数据映射表 + `Object.keys().forEach` 展开，或抽到 `props.utilsJs`。
> 控件级 `props.events[]` 结构同上；`events: []` = 没挂事件。
> 改 JSON 用程序整体读写（json load/dump），改完 `PUT /apis/dynamic/form` 全量保存。

### 10.4 筛选条件 symbol 枚举与实测坑

| symbol | 含义 | symbol | 含义 |
|---|---|---|---|
| EQ | 等于 | GT / GE | 大于 / ≥ |
| NE | 不等于 | LT / LE | 小于 / ≤ |
| ALL_LIKE | 包含 | LEFT_LIKE / RIGHT_LIKE | 左/右模糊 |

```js
// conditionList
[{ tbName: "table_name", field: "field_name", value: "v", symbol: "EQ", otherValue: "" }]
// advanceConditionList（field 带表前缀）
[{ left: false, right: false, connectStr: ' and ', field: "table.field", symbol: "EQ", value: "v" }]
```

**三个实测坑（2026-09-20 弹窗过滤排查）**：

1. **布尔（switch）字段值必须传 `1` 不能传 `true`**：同一份数据对照实验，`major_tool_flag = true/"true"` 都 0 条，
   `= 1/"1"` 才 1 条。数据库侧全部能匹配 ⇒ 问题在后端 JSON→SQL 类型映射。布尔一律传 `1` / `"1"`。
2. **请求体键名是 `conditionDtoList`、字段名 `tbName`**：用 `table` 作键名报「入参错误」。
3. **按钮上 `setInstance(btn, "conditions", [...])` 不一定带上**：实测 conditions 里的条件后端收到的是空；
   放 `advanceConditions` 才真正带上 ⇒ 按钮动态过滤统一走 advanceConditions。

### 10.5 列表 / 树形渲染

> 这些函数在「表单发布」代码区（与列表按钮同区）`module.exports` 返回对象；**签名无参**。

```js
// renderText：单元格文本渲染（★ 实战定稿：列表页改单元格的唯一正规通道）
module.exports = function () {
  return {
    renderText: (value, record, index, code) => {
      // value=该格字段值  record=行数据  index=行号  code=列表列绑定的控件id
      let style;
      if (code === "<列控件id>" && value === "未出库") style = "color:red";
      return `<span class='bst-customTable-cellRender' style='${style}'>` + (value || "") + `</span>`;
    },
  };
};
```

> renderText 要点：① code 是**列绑定的控件 id**不是字段名；② 返回 HTML 字符串，匹配不到的 code 必须
> **原样返回** `(value || "")`，否则整列显示异常；③ 数值先 replace 再 Number（可能带 %/千分位）；
> ④ **不要在列表页用表单那套 DOM 补位**——列表是 div 虚拟表格（`DIV.ant-table-cell` 无 `<td>`）且表单
> stylesheets 不作用于列表页；⑤ 列表页拿不到表单控件值，固定阈值直接写死 bands 数组。

```js
// renderAction：操作列按钮控制
module.exports = function () {
  return { renderAction: (record, btns) => btns.filter(btn => record.id === 1) };
};

// actionWidth：操作列宽
return { actionWidth: 200 };

// renderTitle / onTreeSelect：树形
return { renderTitle: (nodeData) => nodeData.weight === 0
  ? '<span style="color:red;">' + nodeData.name + '</span>' : nodeData.name };
return { onTreeSelect: ({ setSelectConditions, setHeaderTitle, currentNode }) => {
  setHeaderTitle('测试测试');
  setSelectConditions({ conditions: [], advanceConditions: [] });
} };
```

表单编号由**数据库规则**生成，不在前端代码里。查库（只读）：

| 表 | 用途 |
| :--- | :--- |
| `plant.dy_number_table` | 表名 → 规则：`{number_rule_id, table_name}` |
| `plant.dy_number_rule` | 规则头：`{rule_number, name, table_field, autofill}`（`autofill=true` = 保存时服务端自动填） |

```sql
select d.type, d.value_table_field, d.placeholder_num, d.constant_value, d.sort

where d.number_rule_id = (select number_rule_id from plant.dy_number_table where table_name = 'xxx')

```

1. `type:5` 的字段为空时编号**缺段**；编号落库后改字段**不会重编号** → 生成时机放在字段填完之后。
2. `/dynamic/number/rule/generate` 类接口可能不在前端产物里，验证契约别猜——抓一次真实请求，或

## 12. 附录：自定义接口怎么写与怎么调

> 原则（2026-10-21/22 实测定稿）：**一个接口 = 一条 SQL**，script 写成 `db.plant2x.select([...])` 形式。
> 前端事件代码的外壳 `module.exports = function (params, ctx, block) {}` 是**表单事件脚本**的写法，接口里**不认**——别混淆。

**怎么写：**

```js
db.plant2x.select([select * from tae_weather_daily where id >= CURRENT_DATE order by id FETCH FIRST 3 ROWS ONLY;]);
```

- 方括号里是 SQL（以 `;` 结尾）；**script 写多行时第二行起被静默忽略**（返回 200 但不执行，实测）
  —— 需要多语句：拆成多个接口由前端按序调用，或写存储过程。
- **入参用占位符 `#{name}`**，平台做参数化，不要拼字符串（防注入）。
- **出参用 `SELECT` 起头**，平台把它当列表解析。
- 接口注册在 `sys_api_info`（请求方式、SQL、参数），分组在 `sys_group_info`。

**怎么调用：**

- 接口注册后有自己的 path（在平台「自定义接口」页配置），前端照普通接口调：

```js
// 表单/字段事件里
const res = await ctx.http.request("POST", "<自定义接口path>")({ p1: "v1" });
// 按钮事件里（签名 request, ctx, params）
request("POST", "<自定义接口path>")({ p1: "v1" }).then((res) => { /* res.data */ });
```

**存储过程**（跨表 / 事务 / 表名动态都往存储过程里放）：

```sql
db.plant2x.select([CALL generate_project_code(#{table_name}, #{xmbh}, #{code_column}, #{fixed_name});]);
```

<details><summary>存储过程模板：按表名生成项目编号（点开）</summary>

```sql
DELIMITER $$
DROP PROCEDURE IF EXISTS generate_project_code$$
CREATE PROCEDURE generate_project_code(
    IN p_table_name VARCHAR(64), IN p_xmbh VARCHAR(50),
    IN p_code_column VARCHAR(64), IN p_fixed_name VARCHAR(100)
)
BEGIN
    SET @sql = CONCAT(
        'SELECT CONCAT(',
        'LPAD(COALESCE(MAX(CAST(SUBSTRING(', p_code_column, ' FROM 1 FOR 3) AS UNSIGNED)), 0) + 1, 3, ''0''), ',
        '''-', p_fixed_name, ''' ',
        ') AS new_code ',
        'FROM ', p_table_name, ' ',
        'WHERE xmbh = ''', p_xmbh, ''' AND sys_deleteflag = false'
    );
    PREPARE stmt FROM @sql;
    EXECUTE stmt;
    DEALLOCATE PREPARE stmt;
END$$
DELIMITER ;
```

</details>

**其他注意事项**：跨表/事务在存储过程里控制（一个调用 = 一条 SQL）；超 30 秒的大查询分页或加索引；
PG 日期 `to_char(now() AT TIME ZONE 'Asia/Shanghai', 'YYYY-MM-DD HH24:MI:SS')`；标识符 ≤ 63 字符；
**平台会把脚本里的 `"` → `&quot;`、`&&` → `&amp;&amp;`**，模板里提前规避；多环境库不同（GaussDB = PG 语法，
也有达梦 DM 环境，语法兼容 Oracle 风格）。调试：后台「自定义接口 → 测试」按钮；慢 SQL 看
`sys_application_log` / `sys_business_log`。
