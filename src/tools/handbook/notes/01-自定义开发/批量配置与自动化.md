# 批量配置与自动化

> 自定义表单批量配置是重点：给大量表单注入「创建后」编号事件、清理旧回填、批量回归测试。

---

## 1. bestdt 资料库编号自动生成 · 批量配置工具

> 来源：`bst/bestdt资料编号批量工具`。
> 一句话：给「物业管理 > 资料库」下 50 个表单加「创建后」事件，自动生成资料编号，同时清掉新增按钮 clickEvent 里的旧编号回填逻辑。

### 1.1 目录结构

```
bestdt资料编号批量工具/
├─ README.md
└─ scripts/
   ├─ .env.example              # 复制为 .env 填 host/token
   ├─ config.js / http.js       # 基础设施
   ├─ apply-created-event.js    # ★ 注入「创建后」自动编号事件
   ├─ clean-fullcode.js         # ★ 清理新增按钮 clickEvent 的 value:fullCode 行
   ├─ scan-fullcode.js            # 扫描残留
   ├─ audit-prod2.js              # 审计 created
   ├─ check-host.js               # 打印当前 host
   └─ data/plan-final.json        # 50 表清单（表名/formId/编号前缀/表单名）
```

### 1.2 关键接口与位置

| 项 | 值 |
| :--- | :--- |
| 获取表单 | `GET /apis/dynamic/form/{formId}` → `data.formAttributeJson`（字符串） |
| 保存表单 | **`PUT /apis/dynamic/form`**（集合路径，id 在 body，全量替换） |
| created 位置 | `formAttributeJson.props.events[]` 中 `event:"created"` 的 `codeItem.code` |
| 获取按钮 | `GET /apis/dynamic/form/button/{formId}?subFlag=` |
| 保存按钮 | `PUT /apis/dynamic/form/button`（body=整按钮对象） |
| clickEvent | 新增按钮 `permissionCode==="add"`；内容可能是 URL 编码 |

### 1.3 环境切换（PowerShell）

```powershell
# 正式
$env:API_HOST="http://<内网地址>/apis/"
$env:API_TOKEN="Bearer <token>"

# 测试
$env:API_HOST="http://<内网地址>/apis/"
$env:API_TOKEN="Bearer <token>"

# 或改 scripts/.env

```

### 1.4 执行步骤

```powershell
cd scripts
# ① 预览（不写库）
node apply-created-event.js dry
# ② 单表单试点
node apply-created-event.js one tzlk_wy_aqyb
# ③ 全量注入 created
node apply-created-event.js all
# ④ 清理新增按钮旧编号回填
node clean-fullcode.js all
# ⑤ 验证
node audit-prod2.js
node scan-fullcode.js
```

每步写入前自动备份：`data/apply-created-backup.json`、`data/clean-fullcode-backup.json`。

### 1.5 注入的 created 脚本模板

```js
module.exports = function (request, ctx, params) {
  const code = "<资料名称控件id>";
  if (ctx.getValue(code)) return;          // 已有值不覆盖
  const now = new Date();
  const y = String(now.getFullYear());
  const m = String(now.getMonth() + 1).padStart(2, "0");
  const bh = "<前缀>" + y + m + "-<菜单叶子名>";
  ctx.setValue(code, bh);
};
```

控件 id 从表单当前设计实时解析（勿用别环境的值）。

### 1.6 坑

1. 测试/正式 **formId 相同但控件 code 可能不同** → created 用实时解析。
2. 编号尾段用**菜单叶子名**，不要用 `formName`。
3. 保存表单用 **`PUT /apis/dynamic/form`**，不是 `/form/{id}`（405），不是 `/form/attribute`（dyFormFields null）。
4. clickEvent 存储可能 URL 编码，先 decode 再改、保存再 encode。
5. 改前先 `dry` + 单表单试点，再 `all`。

## 2. smartform-autotest — 智能表单自动化测试引擎

> 来源：`D:/zyt/code/ai_zdh_test/.workbuddy/skills/smartform-autotest/SKILL.md`。
> 给 URL / 表单 code / 子系统名 / YAML 配置即可自动跑表单增删改查测试并出中文 HTML 报告。

### 2.1 运行前置

```bash
pip install playwright
playwright install chromium

# Token
export TEST_ADMIN_TOKEN=<token>
# 或 config/secrets.local.yaml 写 test.admin_token / prod.admin_token
```

环境由 `--env test|prod` 指定，base_url 取 `config/env.yaml`。

### 2.2 快速开始

```bash
python -m smarttest.runner --url "http://<host>/web/#/customform/tzlk_hyjyk" --env test
python -m smarttest.runner --code tzlk_hyjyk --name 会议纪要库 --env test
python -m smarttest.runner --config config/smarttest_targets.yaml --env test   # 多表单
python -m smarttest.runner --subsystem 依据类文件 --env test                  # 某分类下全部
python -m smarttest.runner --all --env test                                    # 全菜单遍历
python -m smarttest.runner --subsystem 依据类文件 --limit 3 --env test         # 只跑前 N 个调试
python -m smarttest.runner --all --refresh --env test                          # 强制重新发现菜单
```

跑完打印报告路径，默认 `reports/latest.html`。

### 2.3 常用参数

| 参数 | 作用 |
| :--- | :--- |
| `--url` | 单个表单页完整 URL |
| `--code` | 表单 code（如 `tzlk_hyjyk`） |
| `--form-id` | 表单定义 id：走 API 拉 formAttributeJson，控件识别最准（推荐） |
| `--subsystem` | 子系统/菜单分类名，遍历其下全部表单 |
| `--all` | 遍历左侧菜单树全部表单 |
| `--limit N` | 只跑前 N 个表单 |
| `--headed` | 有头模式 |

### 2.4 YAML 多表单配置示例

```yaml
env: test
headless: true
token_role: admin
report_title: 表单回归测试
targets:
  - name: 会议纪要库
    code: tzlk_hyjyk
    form_id: 14007373f0de41da878616df15c8c525
    tree_id: e6d4212f37e1c74466c6b5d9cfcec17a
  - name: 合同交底文件
    url: http://<host>/web/#/customform/tzlk_htjdwj
```

### 2.5 测试流程

打开表单页 → 点击新增 → 智能填值 → 保存 → 列表断言 → 表单打印（有按钮才测）→ 编辑回显断言 → 删除清理。

### 2.6 结果判定

每步状态 `PASS / WARN / FAIL / SKIP`。表单级取最差：有 FAIL 记 FAIL。

- **WARN ≠ 失败**：多为系统本身限制（表单不支持打印、无编辑删除按钮、必填字段由前置条件生成）。
- 报告含每步截图，落 `logs/smarttest_shots/`。

## 3. 批量配置通用套路

1. **先抓清单**：从表单设计页列表 API 或数据库 `dy_form` 表拿到 formId。
2. **写脚本**：
   - 读：`GET /apis/dynamic/form/{formId}`
   - 改：`formAttributeJson.props.events` / `btns`
   - 写：`PUT /apis/dynamic/form` / `PUT /apis/dynamic/form/button`
3. **dry → one → all**：预览、单表单试点、全量。
4. **备份原对象**：改前把原 `formAttributeJson` 存到本地 JSON，可回滚。
5. **跑回归**：用 smartform-autotest 验证改后表单能正常打开/保存。
