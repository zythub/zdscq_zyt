## 一、查这套映射的 4 个信息源

| 要查什么 | 去哪查 | 关键字段 |
| :--- | :--- | :--- |
| 接口读哪张表 | `sys_api_info` | `script` 里 `from xxx` / `join xxx` |
| 页面地址 | `sys_menu` | `code`（页面 code）、`access_address`、`parent_id` |
| 页面 ↔ 物理表 | `dy_form_field` | `binding_table`、`form_id` |
| 表结构 | `ALL_TAB_COLUMNS` | `DATA_TYPE`、`DATA_LENGTH`（**达梦按字节**） |

**顺带一提**：达梦里 `sys_api_info.script` 是 CLOB，工具层默认只返回前 200 字符，
要拿全文用 `SUBSTR(script, 150, 250)` 分段取，或看 `ALL_VIEWS.TEXT` 看视图定义。

## 三、★ 两个容易踩的维护陷阱

### 陷阱 1：人员分类统计的数字不在「特种作业人员台账」里

| 接口 | 实际读法 | 改哪个页面才生效 |
| :--- | :--- | :--- |
| `ryzz`（人员资质，列表） | 视图 `v_tzzyaqry_rytz` = `tud_tzzyrytz` UNION ALL `tud_aqglrytz` | 特种作业人员台账 + 安全管理人员台账 |
| `ryzzfltjsl`（人员资质分类统计**数量**） | `tud_dfdcsgrytz.gwgzlb` 字段 | **施工人员台账** 的「人员工作类别」字段 |

**`gwgzlb`（人员工作类别）字段只存在于 `tud_dfdcsgrytz` 这一张表。**
`tud_tzzyrytz` 和 `tud_aqglrytz` 都没有这个字段。

实测（DW001）：
```
tud_dfdcsgrytz.gwgzlb 分布：普工 71 / 特种作业人员 30 / 安全管理人员 19 / 测试 1
→ ryzzfltjsl 返回 aqglrytz_count=19, tzzyrytz_count=30, total_sum=49

tud_tzzyrytz 有 42 条，其中 41 条 sfzh 跟 tud_dfdcsgrytz 重叠
→ 两表是同一批人的两个视角，但分类标签只在一张表上
```

**结论**：大屏上"特种作业人员 30 人"，去**施工人员台账**改，别去特种作业人员台账。

### 陷阱 2：老系统迁移的表没有维护页面

2026-10-27 从老系统（MySQL test1）迁了 10 张表到 prp20，**只做了建表 + 接口 + 测试数据**，
没做维护页面：

`VIDEOINFO`、`VIEW_ZHGD_CLJCJL`、`VIEW_ZHGD_RYXX`、`VIEW_ZHGD_RYJCSJ`、
`ZHGD_EMP_RINOUT_TODAY_V`、`ZHGD_MJTJDW_V`、`ZHGD_DWRYQX_V`、`SG_RYXX_M`、
`ZHGD_AQWGH`、`ZHGD_GGLIST`、`ZHGD_GZTJ`

**这些表现在只能靠手工 INSERT 或外部系统（道闸/门禁/海康）通过接口写入。**
要让人能在页面上维护，需在平台新建 customform 表单并绑到物理表
（表结构已按平台规范建好：`id`/`sys_org_number`/`sys_deleteflag`/`sys_createby` 等）。

## 四、怎么自己复现这套查询

```sql
-- 1) 某接口读哪张表
SELECT path, name, method,
       REGEXP_SUBSTR(script, 'from\s+([A-Za-z_][A-Za-z0-9_]*)', 1, 1, 'i') AS 表
FROM sys_api_info WHERE path = '/resource/zhgd/ryzz';

-- 2) 菜单树（三级）
SELECT gp.name AS 一级, p.name AS 二级, m.name AS 三级, m.code, m.access_address
FROM sys_menu m LEFT JOIN sys_menu p ON m.parent_id=p.id
LEFT JOIN sys_menu gp ON p.parent_id=gp.id
WHERE m.del=0 AND gp.id='97ec922a12d1e3b18338a18d5de5d559';

-- 3) 表单字段绑定情况
SELECT binding_table, COUNT(*) AS 字段数 FROM dy_form_field
WHERE binding_table IN ('tud_dfdcsgrytz','tud_tzzyrytz','tud_aqglrytz',
                        'ter_project_daliy_report','tjc_videoinfo','tud_wghzrfg')
GROUP BY binding_table;

-- 4) 视图定义（找底表）
SELECT SUBSTR(TEXT,1,300) FROM ALL_VIEWS
WHERE OWNER='PRPNEW' AND VIEW_NAME='V_TZZYAQRY_RYTZ';

-- 5) 某表有没有菜单
SELECT id, code, name, access_address, parent_id FROM sys_menu
WHERE del=0 AND UPPER(code)='TUD_TZZYRYTZ';
```

⚠️ **注意**：`sys_menu` 里没 `title` 列（是 `name`），`ALL_VIEWS` 里没 `TABLE_NAME` 列（是 `VIEW_NAME`），
`ALL_TAB_COLUMNS` 里 owner 字段是 `OWNER`（大写）。写错列名会报 -2111。

## 五、给用户的话术

**能在菜单里维护的**：智慧工地 → 人_人员管理（施工人员台账 / 特种作业人员台账 /
安全管理人员台账 / 检查区域 / 网格化管理责任区域划分表）；智慧工地 → 进_进度管理 → 施工日报。

需要补页面或由外部系统写接口。
